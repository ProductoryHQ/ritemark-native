Scheduled Tasks Daemon

Revised to use Ritemark's existing components and VS Code native primitives — no invented surfaces. Schedule is authored in the Agent editor; runs live in the Agent Library; toasts and the status bar are VS Code native.

01

Authoring — in the Agent editor

No raw frontmatter. The schedule is a field group in the agent pane, alongside Description / Model / Tools — same SectionLabel + FieldRow pattern as AgentConfiguratorPanel.tsx. It serializes to schedule: frontmatter underneath.

Why this changed

v1 showed a raw YAML block in the editor. Real Ritemark agents are configured through the structured agent pane — the schedule belongs there as a first-class field group, not as hand-typed frontmatter.

The Enabled switch reuses the toggle pattern; Cron is a mono input with an inline help link; Label feeds every other surface.

Implementation: add one SectionLabel + FieldRow group; write-through to fm.schedule.

02

Status barVS Code native · createStatusBarItem

A native status bar item (right-aligned), same idiom as connectivity.ts and the word-count item. Codicon + label text; the warning state uses the built-in statusBarItem.warningBackground. Click runs ritemark.daemon.showScheduledRuns.

Native, not custom

v1 drew a bespoke pill. This is the real VS Code status bar item: $(clock) idle, $(sync~spin) running, $(warning) + amber warningBackground for blocked runs.

No webview involved. One StatusBarItem, text + backgroundColor swapped by state.

03

NotificationsVS Code native · showInformation / showWarning

Native VS Code notification toasts (bottom-right), not custom HTML. Action buttons map to the return value of showInformationMessage / showWarningMessage.

04

Run history — a Library section

Not a bespoke panel. A new collapsible SCHEDULED section in the Agent Library, between COMMANDS and FLOWS — same .section-header and .item markup as every other section (icon chip 32×32, name 13px, description 11px, amber .item-hint).
