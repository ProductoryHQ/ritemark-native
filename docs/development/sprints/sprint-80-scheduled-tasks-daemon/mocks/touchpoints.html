Sprint 80 · UX Touchpoints

Scheduled Tasks Daemon

Every surface a user actually sees when an agent runs on a schedule. Static mockup in the Indigo-Editorial system — for design review before implementation.

5 touchpoints Light theme Ritemark chrome, not VS Code default
01

Authoring a schedule

The only setup interface is the agent file's frontmatter. The user writes a schedule block; Ritemark picks it up live, no restart.

daily-brief.md — my-notes
daily-brief.md
--- title: Daily Brief agent: claude-sonnet-4-6 schedule: cron: "0 9 * * 1-5" # weekdays at 09:00 label: "Daily brief" enabled: true --- Summarise my open tasks, unread items, and calendar for today into a short morning brief.
enabled: false pauses the schedule without deleting it. Editing the cron line takes effect the moment you save.
1 scheduled task Markdown UTF-8
02

Status bar — the live signal

Scheduled runs happen in the background. The status bar is the always-visible signal that one is registered, running, or needs attention. One status item, three states.

Idle — task registered
1 scheduled task Ln 12, Col 4
Running — pulsing
Daily brief… Ln 12, Col 4
Needs attention — blocked run
1 needs review Ln 12, Col 4
Clicking the status item opens Run history (touchpoint 05). The pulse uses the indigo accent only — no green/red traffic-lighting per the design rules.
03

Completion toast

When a read-only run finishes, a dismissible toast surfaces the result without interrupting editing. Shows the label and the first line of the agent's output.

Daily brief finished ×
"Here's your Monday 9 June brief: three meetings, two open PRs awaiting your review, and one overdue task…"
04

Blocked toast — approval needed

Unattended runs auto-approve reads but block writes and shell commands. The toast names exactly what was blocked so the user can decide. Amber, the earned warning tone — not red (nothing is broken).

Daily brief paused — approval needed ×
Agent wants to write to notes/2026-06-09.md. Scheduled runs can't write unattended.
Sprint 80 scope note: the spec defers inline approve-from-history. The "Review & approve" button is shown here as the intended path; if it doesn't land this sprint, the toast degrades to "Show history" only. Decision flagged for the plan.
05

Run history

Lives in the AI sidebar / Agent Library. Every scheduled run — completed, blocked, errored, in-progress — is recorded here. This is the durable record; toasts are ephemeral.
