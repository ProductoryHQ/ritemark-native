# Flow step panel harness (P4)

A static page that runs the committed webview bundle (`extensions/ritemark/media/webview.js`) as the Flow editor, with a stand-in for `FlowEditorProvider`. It reproduces two defects in the step panel without launching Ritemark or a VS Code dev instance:

1. The Delete row at the panel's foot cuts through an LLM step's Temperature and Max Tokens fields.
2. "Loading models..." over a greyed model picker each time a step is selected.

## Files

| File | What it is |
| --- | --- |
| `harness.html` | The page `FlowEditorProvider.getHtml()` builds (its own `<style>` verbatim), VS Code's webview default styles, the theme's `--vscode-*` variables, `body.vscode-light`, and `#root[data-editor-type=flow]` |
| `host-stub.js` | `acquireVsCodeApi` and the host's answers: `ready` → `flow:modelConfig`, `flow:featureFlags`, `flow:load`; `flow:getModels` → `flow:models`, answered with `message.type \|\| 'llm'` as the model type, as `FlowEditorProvider.ts:164` does today; then a click on the LLM step |
| `flow.js` | The flow it opens: Trigger, an LLM step, Save file. Its sample model IDs are made up; real IDs live only in `src/ai/modelConfig.ts` |
| `theme-light.css` | Ritemark Light's colours (`themes/ritemark-light.json` with its includes, plus the `ritemark.*` defaults in `package.json`). Generated by `shoot.mjs` on every run |
| `shoot.mjs` | Opens the harness in headless Chromium over raw CDP (Node 22's built-in WebSocket, no npm packages), measures the panel and saves the screenshots |

## Run it

Headless, measured, with screenshots in `../../../qa/` (`p4-*.png`) and the measurements printed as JSON:

```bash
node docs/development/releases/v2.1.0/sprint-144-release-harness/research/repro/flow-step-panel/shoot.mjs
```

It uses Playwright's cached `chrome-headless-shell` (`~/Library/Caches/ms-playwright`), else Google Chrome with `--headless=new`; `--chrome <path>` picks another. Nothing opens on screen. `--no-shots` measures only.

By hand, in any browser: open `harness.html` as a file, or serve the **worktree root** (the page loads the bundle from eight folders up) and open the page under it:

```bash
python3 -m http.server 8765 --bind 127.0.0.1   # from the worktree root
# http://127.0.0.1:8765/docs/development/releases/v2.1.0/sprint-144-release-harness/research/repro/flow-step-panel/harness.html
```

Size the window to the desk's webview. At a 1440 × 900 window with both columns the desk is 784 × 824 (`docs/development/frame-baseline/light-base.png`: the sheet spans x 256–1039, y 44–867).

Query parameters: `selectAt=<ms>|none` (when the step is clicked after `flow:load`, default 400), `node=<id>` (default `llm-1`), `modelsDelay=<ms>` (the host's answer to `flow:getModels`, default 150), `modelConfigDelay=<ms>` and `loadDelay=<ms>` (a slow host), `replyFix=1` (answer with the webview's own `modelType`, the proposed host fix). The page keeps a timeline of every message in `window.__harnessLog`.

The bundle is the committed one, so rebuild it (`npm run build` in `extensions/ritemark/webview`) before checking a fix here.
