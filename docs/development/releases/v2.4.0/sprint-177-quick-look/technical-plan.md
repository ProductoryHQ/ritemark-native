# Sprint 177 technical plan

## Audit

The [spike](research/2026-11-25-quick-look-spike.md) aimed to show a deck’s first slide in Finder (#953) by rendering on demand in two WebKit extensions. Round 3 (run 45683909718, macOS 15 and 26) supersedes that recommendation. Even a static three-line page failed under A. With the network entitlement, WebContent still crashed on 15 or failed to launch on 26. Keep the two extension points and the build research. Drop the WebKit renderer, view-based preview and JavaScript bundle from the shipping design, including the harness’s `extensions/ritemark/src/decks/quickLook/build.mjs`. The spike’s nil thumbnail reply could hand Finder back to its text thumbnailer. Return an explicit icon reply instead. The spike’s save-only option also missed received or edited decks, which the agreed project sweep and disk watcher cover once Ritemark is running.

## R1–R5 · Draw and keep one PDF

Extract the non-interactive part of `extensions/ritemark/src/decks/deckPdf.ts` for reuse by the current export and the proposed `src/decks/quickLookCache.ts` and `src/decks/quickLookJobs.ts`. Resolve the existing theme and local assets from disk and use the existing slide builder and offline `_ritemark.printHtmlToPdf` from patch 021. Check the renderer can work from saved bytes without an editor or dialog. Reuse the existing missing-theme and missing-picture behaviour. Keep the temporary print directory private and remove it after each job.

**Ground and glow.** On this branch `SLIDES_PRINT_CSS` already uses `--ground` and exact print colours. Patch 021 sets `printBackground: true` and `preferCSSPageSize: true`. The Slides path already specifies 960 × 540 CSS pixels, no paper margins and one page per slide. The locally available #919 change (PR #1065, commit `1a02f4276`, outside this base) fixes the separate A4 print rules. Quick Look uses the Slides rules and has no planned dependency on that merge. Compare rasterized PDFs to the wall for ground, glow, Borderless, fonts and assets before accepting this path. If they differ, fix the shared Slides rendering where possible and re-rate the PR if a shell patch changes.

Use `~/Library/Caches/<bundle id>/quicklook/v1/<sha256 of the real path>/` with one `slides.pdf` and one `entry.json` per deck. Share the canonical path and UTF-8 key rules with Swift and take the bundle ID from the installed product. Record real source path, SHA-256 of the exact .rtms bytes, slide count, app version and draw time. Proposed extra fields are a PDF digest to reject mixed generations and an input fingerprint for the app to notice changed local dependencies or renderer inputs. Agree the schema before either reader lands.

Write private temporary files and atomically rename the PDF, then the manifest as the commit record. Readers verify the digest of the same PDF bytes they use and can fall back during a replacement. Serialize writes and pruning across windows, recheck disk bytes, dependencies and project ownership before publishing, and discard superseded work. Prove interruption and concurrent job ordering. Resolve source aliases consistently and constrain cache reads and cleanup to real, app-owned cache paths. Reject redirects, malformed entries and excessive input sizes. A deck with no printable slide keeps the plain case.

Hook successful saves and a debounced create/change/delete watcher for `.rtms` under open local project roots into the same bounded idle queue. On project open, sweep for missing or outdated entries without opening editors. Use content hashes for freshness, with cheap checks only to schedule work. Define dependency invalidation for local themes, logos and pictures before implementation. The extensions’ mandatory freshness check is against the current deck bytes. Add a default-on darwin platform flag in `src/features/flags.ts` and start the service from activation only when Decks and the print capability are available. Use the Mac app’s cache identity for this build and test older shells, including the case where the print command exists but the Quick Look bundles do not.

Keep enough local project ownership to purge on project removal, including jobs in flight and overlapping roots, and handle file deletion or rename. Closing a window stops its queued jobs. The manager needs to confirm the exact project-removal event and multi-window ownership rule. Prune missing sources first, then oldest drawings to a bounded byte budget. Oversize PDFs leave the plain case. Agree budgets and scheduling based on large projects and folder-thumbnail timing.

## R1–R3, R5 · Native readers

Use `macos/quicklook/Shared/` for lookup and validation, `Thumbnail/ThumbnailProvider.swift` for a native CGPDFDocument page 1 draw and `Preview/PreviewProvider.swift` for a data-based `QLPreviewProvider`. Both match exactly `ai.productory.ritemark.deck`. Set `QLIsDataBasedPreview` true and keep searchable items false. Both extensions are sandboxed with A’s home-relative read-only exception, with no network or cache-write entitlement. Prove they can read the installed bundle resources, source and cache on each OS. A URL outside the readable home may only get readable text if macOS grants access to the requested file. Prove the handoff on external volumes and with local cloud copies. Report a read error if the source bytes are inaccessible.

Resolve and hash the current source before serving a validated PDF. Use the bytes of that read for the text reply on a mismatch. Check for a replacement during the request. On a hit, set the PDF reply’s type to PDF and let Quick Look draw it. For a thumbnail miss, always complete with a drawing reply using the app bundle’s deck icon, including on timeout. Sprint 172 stamps a badge and DECK text for macOS to compose the system page. There is no stand-alone document icon file today. First prove a native type-icon lookup using the bundle registration and compare against the 2.3 document icon. If it recurses, loses the badge or returns another icon, the Experience lead makes a bundled icon from `product/design/experience/experiences/decks/file-icon/` (the white page with the folded corner and the indigo easel, the Windows icon already); the build gives her the sizes, and the resource joins build validation. Below 64 px the thumbnail always draws the deck icon (never an empty reply, which could hand Finder to its text thumbnailer).

Finder can reuse a thumbnail without asking the extension. Direct hash checks do not prove S3. Test a warmed Finder cache without resetting it, including changes while Ritemark is closed and after installing over 2.3. If Finder serves stale pictures or text thumbnails, bring observed cases and supported invalidation options to the manager before calling the Finder contract met.

## R6 · Build, sign and discover

Create `scripts/build-quicklook.sh` to compile both `.appex` bundles with `swiftc`, `_NSExtensionMain`, macOS 12 and arm64 plus x86_64 joined with `lipo`. Install them in `Contents/PlugIns/` from `scripts/build-prod.sh` and `.github/workflows/build-macos-x64.yml` before signing. In `scripts/codesign-app.sh`, sign each nested bundle with its own entitlements, hardened runtime and secure timestamp before signing the app. Check deep strict verification and Developer ID notarization at release. In `scripts/validate-build-output.sh` check IDs, versions, deployment target, slices, exact content type, preview mode and fallback resources. Cover native source at the release commit and built PlugIns before signing in `scripts/build-provenance.mjs`, record Swift and SDK versions and carry checks through x64 artifact extraction.

Add `macos/quicklook/` and `scripts/build-quicklook.sh` to the shell-tier list in `CLAUDE.md` and the identical `SHELL_TIER_PATHS` in `scripts/release-extension-preflight.sh` in the same commit as the shipping paths. Reuse the existing list entries for build and signing scripts. The planned app-side cache code can be extension-tier by path and ships with 2.4’s full app.

Release builds use a new `scripts/create-release-worktree.sh` checkout at the exact `origin/main` commit, with independently materialized dependencies, canonical patches, no symlinked or pre-patched VS Code and no reused output. Build, signing and packaging verify matching embedded provenance. Keep generated proof and build files outside the source tree. Gate 1 covers arm64 and Gate 2 covers Intel and Windows as set by the release plan.

Prove the labels and result before placing instructions in Ritemark Help or release notes. Keep signed and notarized candidate results distinct from runner results.
