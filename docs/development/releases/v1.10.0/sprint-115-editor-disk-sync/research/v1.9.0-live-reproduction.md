## Isolation and Observation Method

The released application was launched as a separate instance with a disposable profile and a dedicated Chrome DevTools port. The existing user session was not stopped or modified.

```text
open -na /Applications/Ritemark.app --args \
  --user-data-dir /private/tmp/ritemark-sprint-115-v190-profile \
  --disable-workspace-trust --disable-telemetry \
  --remote-debugging-port=9224 \
  /private/tmp/ritemark-sprint-115-v190-fixture/sync-audit.md
```

The fixture was a disposable standalone Markdown file. CDP snapshots recorded the TipTap `.ProseMirror` text, focus class, and header-button accessibility text. Exact disk bytes were read independently. A macOS screenshot captured the wrong active Space and was discarded; it is not treated as evidence.

The released build has no host-side trace points for watcher, poll, `TextDocument`, send, or receipt timing. Model state was therefore tested indirectly and conclusively through Save followed by a disk read. The implementation sprint must add content-free transition diagnostics for the full timeline.

## Reproduction A — Focused External Write Remains Invisible

1. Opened and focused a saved baseline containing `DISK_REVISION=AGENT-B`.
2. Replaced the disk line externally with `DISK_REVISION=AGENT-C`.
3. At `2026-08-24T17:40:19.814Z`, the disk contained C while the focused ProseMirror still showed B. No sync action was visible.
4. At `2026-08-24T17:40:28.794Z`, after more than two three-second poll intervals, the view still showed B and no action was visible.
5. Blurred the editor by focusing a header control. At `2026-08-24T17:40:53.824Z`, the view still showed B and no action was visible.

This is the reported close/reopen defect. It also proves there is no effective blur retry: once the host marks the disk hash as sent, later level polls do not resend it.

## Reproduction B — The Ten-Second Path Discards Model Work

The isolated profile used `"files.autoSave": "off"`.

1. The disk contained `DISK_REVISION=AGENT-E`, while the stale visible editor still showed the older B content.
2. Entered 25 local one-character edits into the visible editor.
3. At `2026-08-24T17:45:57.499Z`, ProseMirror showed B plus the local edits, the disk still contained E, and **File changed on disk** was active.
4. Waited more than 12 seconds. At `2026-08-24T17:46:23.712Z`, the visible editor still showed B plus the local edits and the action was still active.
5. Invoked Save. The disk remained exactly E and contained none of the local edits. Therefore the VS Code `TextDocument` had already been replaced with E even though the webview still displayed the local content.
6. Reloaded the isolated window. At `2026-08-24T17:47:05.748Z`, the view showed E and all 25 local edits were gone.

This confirms the source-audit P0 finding in the released v1.9.0 binary: the fixed timer can replace unsaved model content without a user resolution, while the stale webview conceals that transition until reconstruction.

## Reproduction C — False Disk-Change Action Without a Disk Change

1. Converged disk, model, and view to `DISK_REVISION=BASELINE-F`; at `2026-08-24T17:48:23.397Z`, no sync action was visible.
2. With autosave off and no further external write, entered 26 one-character local edits ending in `LOCALONLY1234567890ABCDEF`.
3. At `2026-08-24T17:48:52.417Z`, ProseMirror contained the local text and the header exposed:
   - accessible label: `File changed on disk - click to refresh`
   - tooltip: `File changed on disk - click to reload`
4. An independent disk read still returned the exact BASELINE-F file and did not contain `LOCALONLY`.

The action therefore does not represent a real filesystem change. The observed 26-step sequence is consistent with the audited 20-entry self-hash eviction: ordinary working-copy edits eventually make the unchanged disk base look foreign.

## Conclusions

- Message posting is not visible application. The host needs an exact revision/payload receipt from each webview epoch.
- Focus cannot suppress an authoritative update without a queued retry/application path.
- A local-only working copy legitimately differs from disk and must remain quiet.
- Conflict classification needs base/disk/model three-way state; `isDirty`, current disk/view inequality, and bounded self-hash history are insufficient.
- No timer may resolve, reload, or discard a conflict.
- The `TextDocument` must remain the editable authority; disk observations must reconcile through it before a view update.
