- Pick a deck's theme and look from one **Theme** button on the deck's bar ("Evening ▾"). Card | Borderless moves there from the slide's settings.
- Make a new theme, starting from the deck's own, Paper or Ember, and edit it in its own tab: four colours, soft light, fonts, logo, corners and boxes, previewed on six of the deck's slides, saved with Save.
- Ask Claude "make this deck look like our brand". Claude makes the theme from the folder's brand guide, logo or a `.pptx`, and offers See what changed and Undo.
- The wall and the published page show the theme with its fonts and logo. A page changes only with Update the page.

## PR 1 as built
- **The Theme button** (`webview/src/components/decks/ThemeMenu.tsx`) sits on the deck's bar, on the right before Saved: the theme's colours as a small swatch, its name and ▾. Its menu is a Radix popover (it closes on a press outside and on Esc and gives the focus back to the button): LOOK, Card | Borderless, written by the same `setLook` as before; then THEME, the files in `Slide library/Themes/` and the built-in Evening when the project has no file for it, each with its swatch, its name and how many of the project's decks draw it, the current one ticked. The host lists them each time the menu opens (`deck/themes`, `deckPages.themesFor`, `deckTheme.themeEntries`).
- **Which theme a deck draws, for the tick and the count:** the file its `theme:` line names when the project has it (whatever its slashes or case); otherwise (no line, or a file that isn't there) the built-in theme, as the engine draws it. A project's own `Evening.theme.md` is Evening in that project (the Experience lead, 17 November): such a deck draws that file (the view, the wall, the page and the library's thumbnails read it), is counted under it, and its row is ticked; there is no second Evening row.
- **A pick** writes the deck's `theme:` line, always naming the file's path (Evening's too, as New → Deck writes it), so a deck stays linked to the project's own Evening file once there is one. It is one step of the deck's Undo (`webview/src/components/decks/theme/themePick.ts`): a history step that leaves the document as it is and carries the line's value before and after, so Cmd+Z anywhere in the deck, and the bar notice's Undo, take it back, and Redo writes it again. The front matter changes only on that line, in the quotes it had (`editorSync/frontMatter.headWithPlainKeyChanges`), so one Undo gives the file back byte for byte. The bar says "This deck uses <Name> now." with Undo. Card | Borderless in the same menu is a step of the same Undo. An Undo or Redo whose line was changed since by someone else (the AI, another program) leaves the newer value and says so.
- **The slide settings popover** keeps only the slide's own settings. Its "This deck" section held only Card | Borderless, which is now in the Theme menu; the strip's Deck look… (for a deck with no slides) went with it, since the Theme button is there at any count.
- **The wall's bands** take the theme's ground at the darker end of its soft light (a Borderless deck's are white), not step 2's fixed #0E0C24.
- **When the bar is short of room,** what gives way, in order: the Theme button's name (its swatch and ▾ stay, the name is in its tooltip), Publish's word, the notice's words, and Present's word last.
- **Not in PR 1:** Edit <Name> and New theme… (they open the theme's tab: PR 2). Only Sofia Sans renders until PR 3.

## PR 2 as built
- **The tab is a mode of the Markdown editor**, as a deck is: a `Slide library/Themes/<Name>.theme.md` in the project opens as the theme's tab (`themeMode`), named after the theme. The draft is the theme document's unsaved text, so the dot, Save and Cmd+S, the close question and a window reload come from VS Code. Each change writes only that field's line, in its quotes (a colour change also drops the hand-picked shades, as the prototype does); a theme opened and closed unchanged stays byte for byte. Theme files don't auto-save (`[ritemark-theme]` `files.autoSave: off`); the decks read the file on disk, so they change only on Save, and then at once.
- **On the bar:** the swatch and name, "Used by N decks" (a list; a deck opens from it), Saved or Not saved with Discard, and Save ▾ (Save as a new theme…, Discard the changes). After Save the bar says how many decks have the new look, with Undo.
- **In the tab:** the four colours (a palette swatch and a hex code each), Soft light in a corner, the contrast line (text and headings against the background, 4.5 to 1), Corners and Boxes, and six of the deck's slides as Card or Borderless. No fonts or logo yet (PR 3, PR 4).
- **The Theme menu** has Edit <Name> (not for the built-in Evening while the project has no Evening file) and New theme… (a copy of the deck's theme, Paper or Ember, "Use it in this deck" ticked).
- **The name rule** (for the Experience lead): a new theme's name is its file's name. It may not be a name or file another theme in the project has (Evening included), in any case; it holds no / \ : * ? " < > | #, starts with a letter or digit, doesn't end with a full stop, and has at most 60 characters. A name that breaks it is refused with the reason; nothing is renamed for you. Save as a new theme… offers "<Name> 2".
- **The Experience lead (17 November):** the draft bar says what Save will do ("Not saved. Saving changes 2 decks.", the count opens the decks' list); a theme file and its tab show Lucide's palette (the file icon theme's `theme.md`); a refused name says why under the field as it is typed, and Make the theme stays disabled with the reason as its tooltip. Cmd+Z in the tab steps the draft back.
- **The close question** is VS Code's own, without the list of decks: accepted for 2.3 (the Experience lead, 17 November), no patch.

## PR 3 as built
- **The fonts** are in `extensions/ritemark/media/fonts/` beside Sofia Sans, as `<Font>-latin.woff2` and `<Font>-latin-ext.woff2`: variable woff2, weight axis only, upright, in Google Fonts' latin and latin-ext cuts (Estonian's õ ä ö ü are in latin, š ž in latin-ext). They come from the `@fontsource-variable` packages, which repackage Google Fonts' `google/fonts` releases: Inter 4.001 (`@fontsource-variable/inter` 5.3.0), IBM Plex Sans 3.201 (`ibm-plex-sans` 5.3.0), Space Grotesk 2.000 (`space-grotesk` 5.3.0), Source Serif 4 4.004 (`source-serif-4` 5.3.1) and Fraunces 1.000 (`fraunces` 5.3.0). The five add 414,580 bytes. All six are SIL OFL 1.1; `media/fonts/OFL.txt` holds each one's version, files, source and copyright line (from the font file's own name table) and the licence text, Sofia Sans's too, which had no notice before.
- **The names** (`src/decks/deckTheme.ts`, `deckFont`): a theme's `heading-font` and `text-font` match one of the six whatever their case and spacing; any other name, or none, draws in Sofia Sans. A slide's `--s-fh` and `--s-fb` are the font, then Sofia Sans (while it loads, or if its file is missing), then its kind (`sans-serif` or `serif`). The theme file keeps the name as written.
- **The slide, the strip, the wall, the presenter view and the Slide library** draw them through `@font-face` rules on the files beside `webview.js` (`webview/src/components/decks/theme/deckFonts.ts`, installed once in `main.tsx`), not inlined into `webview.js` (#107): a rule loads its file only when a slide uses its font. A legacy-layout slide now measures its fit again when a font loads or the theme's fonts change, as a block slide already did.
- **The published page's content wears the theme** (the Experience lead, 17 November; step-3-themes.md): the session's title in the top bar, the part headings, the preamble's headings and Contents' entries take the heading font (`--fh`), the handout's text the text font (`--fb`); the page's own controls (the client's name, the count, Contents' button and header, the eyebrows and labels, the arrows' caption, Copy, the footer and the toast) keep Sofia Sans. The editor's handout keeps the editor's own type.
- **The published page** carries Sofia Sans inline as before (its controls use it) and the theme's other fonts as files in a `fonts` folder beside the page, `fonts/<Font>-<version>-<part>.woff2` (this place and these names approved by the Experience lead, 17 November), written just before the page, only the theme's fonts, and once for all the decks in a folder. 2.2's gather finds them in the page's style and sends them with it. The page's CSP reads `font-src 'self' data: file:`; it loads no font from anywhere else. A name in `fonts/` taken by another file, or a `fonts` that is a file or a link, stops Publish in one line and is never touched; the version in the name means a later font release never meets an older file. A cancelled first Publish (or a page that couldn't be written) takes back the fonts it wrote, unless another page of Ritemark's in the folder names them or another Publish in the window is using them, and the `fonts` folder only if it made it. The page's digest counts the font files it names, so a page made before the fonts could go reads "Published · changed". The sheet's What goes ends "…, and the theme's fonts." when files go.
- **Delivery:** the font files reach people only with a full (shell) release, which 2.3 is. `media/fonts/*` is outside what an extension release ships, so `scripts/release-extension-preflight.sh` lists the ten new font files and `OFL.txt` as unshipped and stops unless `--allow-unshipped`. Code from this PR on an app without the files draws Sofia Sans and writes no font files.
- **The two font pickers** (Headings and Text, each from the six) are rows in the theme's tab (PR 2's), after Corners and Boxes; a pick is one field line in the draft, saved with Save like a colour.

## PR 5 as built
- **The DECKS instructions** teach themes in four short lines, the same for Claude, ChatGPT and OpenCode (`capabilityContext.ts` v5): the `.theme.md` in `Slide library/Themes/` and the deck's `theme:` line, the fields the reader reads, the six fonts by exact name (from `DECK_FONT_LIST`), 4.5 : 1 for text and 3 : 1 for the accent, "change the theme file, never individual slides", the closest-font line, and "this deck or all of them?" when the folder holds more than one deck.
- **Four tools in the one registry** (`DECK_TOOL_GROUP`), so no runtime has its own: `read_pptx_theme` (a `.pptx`'s theme colours and fonts as JSON, nothing else of the file), `set_deck_theme` (makes or changes a theme and points decks at it; fonts only the six; a new theme needs its four colours), `check_theme_colours` (the five pairs, with the nearest passing colour) and `set_theme_draft_colours` (an open theme tab's draft, never saved). The instructions tell the AI never to write a theme file or a `theme:` line by hand, since only a tool's write is recorded for Undo.
- **See what changed, Undo, Open the theme** under the reply (frame 13), for every AI. The existing flow had none of these: the sidebar only listed "Modified N files", so the change record is new (`themeAi.ts`, in memory: a window reload forgets it, and Undo then says so). See what changed is a sheet over the deck's stage, the strip and the chat in view: the deck's first slide and its first with Boxes, Steps or Columns, each "Before · <old>" beside "After · <new>", drawn by the strip's renderer; Undo and Close (Esc, a press outside). Undo puts each deck's `theme:` line back as it was (byte for byte) where it is still the change's, and removes the new theme only if no deck uses it and it is as the AI wrote it; otherwise it stays and the reply says "Kept <Name>: you changed it after I made it." (or "another deck uses it").
- **Claude's colour check** sits on the contrast line (the Experience lead, 17 November): "Check all colours" at rest, "Fix with Claude" when the line is amber. It sends its request to the open chat as the person's message (queued behind a running turn), with no question first. The colours land in the draft (dot, Not saved); the decks change only on Save. A theme's tab in front gives the AI's empty chat the starting point "Check that the colours are easy to read".
- **Not in PR 5:** a logo field (PR 4); a record that survives a window reload; See what changed for a theme change whose deck has no slides (the sheet says so).
