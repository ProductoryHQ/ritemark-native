# Sprint 168 spec

The README is the spec. It lives in the governance repo at `product/design/experience/experiences/decks/README.md`, section "Quotes, prompts and heading levels on a slide" (ritemark-dev commit 1d0f3f6), with the sketch in `quote-on-slide.html` beside it. This file only numbers the requirements so the scenarios and tasks can point at them. Where this file and the README differ, the README wins.

- **R1 (README item 1).** The quote has no fill and a 3 px inset bar in the full accent, `var(--s-acc)`, with `padding-left: 18px` and `margin-bottom: 12px`. The words are `--s-hd` at 1.08em, weight 500, line-height 1.4, with 6 px between paragraphs. A last paragraph that starts with "— " or "– " is the attribution: 0.74em, weight 600, `--s-sub`, 10 px above. In the file it is just the quote's last line. It looks the same on the editor (live), wall, presenter view, strip and page, on dark and on Paper. It builds on #841's leak fix.
- **R2 (README item 2).** On a slide, Code block applied to words inside a blockquote, from the bubble or the / menu, takes them out of it. The chosen paragraphs become one code block at that place, with Copy and ↗. A quote left empty goes. The whole change is one undo step. No new button: the command is the existing `toggleCodeBlock`.
- **R3 (README item 3).** Heading order on a slide follows the document. In `slide.css`, h2 goes from `600 1.12em --s-sub` to `700 1.3em --s-hd`, and h3 from 1.25em to 1.15em. An h2 directly after the h1 keeps weight 500 and `--s-sub` (the title's line) at the same 1.3em. A box's h3 stays as it is. The slide's / menu items become Heading 1 (#), Heading 2 (##) and Heading 3 (###); "Title" and "Heading" go. Hidden words: Heading 1: title, h1, pealkiri. Heading 2: subtitle, subheading, h2, alapealkiri. Heading 3: heading, h3. The bubble keeps H1/H2/H3. Decks whose h2s grow step their words down through the fit as usual.
- **R4 (HARD RULE #1).** The / menu's rename keeps both functions, and R2 changes where the code goes, not whether it exists. Neither is a removal by this plan's reading; the sprint plan says so and asks Jarmo. Anything else that goes waits for his yes by name.

- **The Experience lead, 19 November:** a quote whose only line starts with a dash is drawn as the quote's words, in the quote's own look; an attribution needs words above it in the same quote. The class written by the renderer and the node view is fine. PR 1's proof shows both surfaces and a two-line quote whose second line starts with a dash.
