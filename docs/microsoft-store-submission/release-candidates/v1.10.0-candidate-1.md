## Blocking defect — Codex file tools on Windows

Found 2026-09-07 during Windows testing of this exact hash.

Every Codex turn that reads or writes a file fails, in the default and "recommended"
sandbox mode ("Workspace write — read and write within project"). The runtime error is:

```
exec_command failed: CreateProcess Rejected("Failed to create unified exec process:
orchestrator_helper_launch_failed: setup refresh failed to launch helper:
helper=codex-windows-sandbox-setup.exe, error=program not found")
```

**Root cause.** `extensions/ritemark/binaries/agents/manifest.json` declares only
`codex-app-server` and `codex-code-mode-host` for `win32-x64`. The official Codex
win32-x64 vendor package also ships `codex-windows-sandbox-setup.exe` and
`codex-command-runner.exe` (~0.7 MB each), which the sandboxed exec path requires.
Neither is present anywhere in the installed tree.

**Workaround, not a fix.** Setting Sandbox Mode to full access makes Codex work, because
that path never spawns the helper. Shipping with the recommended mode broken is not
acceptable.

**Resolution.** Fixed on `fix/codex-windows-sandbox-helpers` and released as Windows-only
**1.10.1**. macOS is unaffected — the helpers exist only for Windows, because macOS sandboxes
Codex through the OS seatbelt — so the notarized macOS 1.10.0 artifact stands.

Verified on 2026-09-07 by dropping the two vendor binaries into an installed 1.10.0 tree and
re-running a Codex file read in the default `workspace-write` sandbox mode. The Codex sandbox
log went from `program not found` to:

```
setup refresh: spawning ...inariesagentswin32-x64codex-windows-sandbox-setup.exe
codex-windows-sandbox-setup.exe] setup binary completed
helper copy: recopied command-runner ... destination=....sandbox-bincodex-command-runner-0.153.0.exe
helper launch resolution: using copied command-runner path ...
```

and the agent correctly answered a question that required reading the file. Note that Codex
0.153.0 stages the command runner as `codex-command-runner-0.153.0.exe`, so a stale unversioned
copy from an unrelated npm Codex install does not satisfy it — both binaries must be bundled.

This is the same class of defect as the macOS candidate's missing `codex-code-mode-host`
sibling recorded in `docs/releases/v1.10.0/TEST-CHECKLIST.md` — a Codex sibling binary
omitted from the manifest — this time Windows-specific.
