# Ritemark 2.3.0 Test Checklist

> **Started on 16 November 2026** at the close-out of Sprints 159 and 160, before 2.3's release plan and candidate exist. It holds what those two sprints couldn't run, for Jarmo to test on the release candidate. The candidate's table, the Gate 1 and Gate 2 rows, Sprint 158's Not run rows and the sign-off are added when the candidate is built, as in [2.2's checklist](../v2.2.0/TEST-CHECKLIST.md).

Where the rows come from: [Sprint 159's close-out](../../development/releases/v2.3.0/sprint-159-decks-training/sprint-plan.md#close-out) and [Sprint 160's](../../development/releases/v2.3.0/sprint-160-ai-ready-day-one/sprint-plan.md#close-out).

- **Your own profile** is the main test. Rows marked **Fresh** run in a test instance with its own throwaway folders and AI homes, started as in [2.2's How to start](../v2.2.0/TEST-CHECKLIST.md#how-to-start).
- **What a row needs** is in bold at its end: **Projector** = a projector or a second display, **Clicker** = a presentation clicker, **Cloudflare** = Jarmo's Cloudflare test account, **Phone** = a real phone, **Windows** = a Windows PC, **AI** = a real signed-in AI (named), **Key** = a real API key (named), **Fresh** = a fresh profile. No mark means the candidate alone is enough.
- **The source** is in small text at the end: the sprint, its PR and the PR's number.
- Tick a row only when it passes. A row that fails gets its issue number beside it. A row not run says why and stays unticked.

## Decks (flag on: `"ritemark.features.decks": true` in user settings)

Add the line to your user settings, then open a deck; the [demo project](../../development/sprints/sprint-157-decks/demo-project/README.md) has several. The Slide library comes after Tasks, and New has Deck.

1. [ ] **The wall on a projector.** Connect the projector and press Present. The slide fills the projector, full screen at 16:9 with dark bands, and nothing of Ritemark shows: no title row, tabs, project name or desk edge. **Projector** <sub>159 PRs 5 and 6, #731, #736</sub>
2. [ ] **The presenter view on the laptop.** With the projector connected, it comes on by itself, and Present's menu names the display ("Slides on <name>, notes here"). It shows the slide now and the next one, the notes (A− and A+ change their size), the row of slides, the clock and Next, in Ritemark Dark, with "Claude and notices wait until you stop." Esc closes both windows, and the deck is back on the slide you ended on. **Projector** <sub>159 PR 6, #736</sub>
3. [ ] **Swap displays.** The wall and the presenter view change displays, each still full screen. Swap again, and they are back as they were. **Projector** <sub>159 PR 6, #736</sub>
4. [ ] **A clicker.** Its forward and back buttons move the wall, whichever of the two windows has the focus. **Projector, Clicker** <sub>159 PRs 5 and 6, #731, #736</sub>
5. [ ] **Publish a deck.** Press Publish on the deck's bar. The sheet's line under its title reads "People open it in their browser, on a computer or a phone.", and What goes and What stays count this deck's slides, prompts, speaker notes and skipped slides. Publish it. The chip reads Published; See online opens the page, and Copy link copies its address. **Cloudflare** <sub>159 PR 4, #737</sub>
6. [ ] **The page on a phone.** Open the address on your phone. The slide stays at the top and the text scrolls under it; Copy on a prompt says Copied (or "Tap Copy in your phone's menu"); an exercise's ticks are still there after a reload; Contents works. No speaker notes and no skipped slide are on the page. **Phone, Cloudflare** <sub>159 PR 3, #729</sub>
7. [ ] **Safari and Firefox.** The same page on a computer, in each: the slide on the left with arrows under it, the text scrolling on the right, and the slide following the text. **Cloudflare** <sub>159 PR 3, #729</sub>
8. [ ] **Update the page.** Change a slide's words: the chip reads Published · changed. Update the page, and the page shows the change. Then change only a speaker note: the chip stays Published. **Cloudflare** <sub>159 PR 4, #737</sub>
9. [ ] **Unpublish.** From the chip's menu. The address no longer shows the page, and the bar shows Publish again. **Cloudflare** <sub>159 PR 4, #737</sub>
10. [ ] **Sprint 157's checklist on the candidate.** Run [Sprint 157's rundev checklist](../../development/sprints/sprint-157-decks/qa/rundev-checklist.md) with the flag on. It ran on the Decks branch, never on main after the merge. <sub>159 PR 2, #735</sub>
11. [ ] **A fresh profile with the flag already on.** Write the line into a fresh profile's user settings before its first start. The Slide library is in the places row from the first frame, after Tasks, and nothing in the row moves. **Fresh** <sub>159 PR 1, #733</sub>
12. [ ] **The bundle's cost.** With the flag off, a long Markdown document opens as fast as in 2.2.0: time it from a cold start on both. Every editor now carries Decks, about 258 KB more. <sub>159 PR 2, #735</sub>
13. [ ] **Decks on Windows.** On a Windows PC: a deck opens as a deck, New → Deck makes "<deck name> (copy)" beside it, Present works on one display, and Publish and the page work as in rows 5–9. The second display on Windows is its own short task. **Windows** <sub>159</sub>

## AI ready on day one

14. [ ] **A Windows cold start (#703).** On a fresh Windows PC, or a Windows user that has never signed in to Claude, start the candidate. Claude shows Sign in, never signed in. Sign in: Claude reads ready, and the first question answers. If Claude shows Sign in after you signed in, the window's console (Help ▸ Toggle Developer Tools) has a `[ritemark]` warning saying why Claude's check gave no answer (`timeout`, `too-much-output`, `spawn-error` or `no-json`); copy it into #703, with whether a `.credentials.json` is in the `.claude` folder in your user folder. **Windows, Fresh, AI: Claude** <sub>160 PR A, #732</sub>
15. [ ] **A real Anthropic key (#541).** In a test instance with no Claude sign-in, save a real Anthropic key in Settings. Claude reads ready on the AI's sheet, the welcome, Home and Settings; a chat answers, and a Flow's Claude step runs. **Fresh, Key: Anthropic** (test-keys row S4) <sub>160 PR A, #732</sub>
16. [ ] **A wrong key.** Change the saved key to a wrong one. Claude still reads ready, and the first message ends on "Claude did not accept the saved key…" with Update key. Write down how long it took: against a stand-in, Claude Code retried for about 4 minutes first. **Fresh** <sub>160 PR A, #732</sub>
17. [ ] **The sign-in wins over the key.** Signed in to Claude with Claude.ai and a key saved too, send a chat: it runs on the sign-in, and the key's usage in Anthropic's console doesn't move. **AI: Claude, Key: Anthropic** <sub>160 PR A, #732</sub>
18. [ ] **A sign-in that finishes while the sheet waits (#696).** In a test instance with no AI signed in, start Claude's sign-in on Home, then look at the AI's sheet: Claude's card waits ("Signing in…", with Cancel) and says your browser opened Claude's sign-in page. Finish the sign-in in the browser: the sheet goes to the chat, and no second Sign in showed. Then ChatGPT: while its sign-in waits, "Did nothing open? Open the page again" opens the same sign-in page again, and Cancel puts the card back as it was. **Fresh, AI: Claude, ChatGPT** <sub>160 PR B, #730</sub>
19. [ ] **A Gemini limit through OpenCode.** With a Google key whose quota is used up: the card reads "You've used <model>'s limit for now", says when it can answer again if Google said, and offers Use <another model>. The rail and the chat list read "Limit reached", and the rail's tooltip names the model. The next message has no "The previous agent did not return a saved answer." Write down Google's own words, and whether it sent `Retry-After`. **Key: Google** <sub>160 PR C, #734</sub>
20. [ ] **Claude's limit.** When Claude's plan limit is reached: the card says so, the rail and the chat list read "Limit reached" with the tooltip "Stopped at Claude's usage limit", and the next message has no "did not return a saved answer". Write down Claude's own words. **AI: Claude** <sub>160 PR C, #734</sub>
21. [ ] **ChatGPT's limit.** The same as row 20, for ChatGPT, with "Stopped at ChatGPT's usage limit". ChatGPT's "busy right now" card isn't a limit, and keeps "Interrupted". **AI: ChatGPT** <sub>160 PR C, #734</sub>
